# BeBeam 앱 제작 규칙 (AI용)

> 이 문서는 **AI(Claude, ChatGPT, Gemini 등)가 먼저 읽는 문서**입니다.
> 주소: https://www.bebeam.net/README.md

## 0. AI에게

사용자가 이 주소를 주며 BeBeam에서 쓸 앱을 만들어 달라고 했다면, 이 문서를 **끝까지 읽고** 아래 순서와 규칙을 지키세요. 사용자는 짧은 한 줄만 붙여 넣었을 수 있습니다. 이 문서가 곧 작업 지시서입니다.

- 결과물은 **`index.html`로 시작하는 폴더 하나**짜리 웹앱입니다. 빌드 도구 없이 바로 열려야 합니다.
- **파비콘(§5)과 대표 스크린샷(§5-1)은 필수**입니다.
- 규칙을 지키지 못하는 기능을 요청받으면, 왜 안 되는지와 대안을 사용자에게 먼저 알려 주세요. 예: 외부 API 호출, 온라인 랭킹.

### 할 일 고르기
- **A. 새로 만들기**: 아래 "작업 순서"와 "묻는 항목"을 따릅니다.
- **B. 이미 만든 앱 바꾸기**: 사용자가 이미 만든 앱의 폴더·파일을 주며 BeBeam에서 실행되게 점검·변환해 달라고 했다면 **§12**를 따릅니다. 원본은 그대로 두고 복사본을 고치며, **콘텐츠는 승인 없이 절대 바꾸지 않습니다**.

### 작업 순서 (A. 새로 만들기)
1. **바로 만들지 말고 먼저 묻습니다** (아래 "묻는 항목"). 사용자가 이미 자세히 설명했다면 빠진 것만 묻습니다.
2. 답을 들을 때마다 짧게 정리해 보여 주고, 빠지거나 애매한 것은 더 묻습니다.
3. 충분히 정해지면 한 장짜리 **기획서**로 요약해 보여 줍니다. 사용자가 "좋아, 시작해"처럼 시작하라고 확인한 뒤에 개발합니다.
4. 개발할 때는 이 문서의 규칙(§2–§7)을 지킵니다. **작업용 스크립트와 임시 파일은 `.work/` 폴더에만** 두고, `.gitignore`를 씁니다(§2-1).
5. 다 만들면 **§9 점검표**를 하나씩 스스로 확인하고, **§10 마치며**대로 사용자에게 알립니다.

### 묻는 항목
- 한 번에 2–3개씩 나눠 묻습니다. 친절하고 자세하게 묻습니다.
- 사용자가 잘 모르겠다고 하면 예시나 선택지를 2–3개 보여 주고 고르게 합니다.

1. 앱 제목
2. 목적: 누가, 언제, 왜 쓰는지 (예: 수업 시간에 반 친구들과 함께 푸는 퀴즈)
3. 종류: 게임 / 수업자료 / 도구 / 기타
4. 스토리라인과 흐름: 시작부터 끝까지 사용자가 겪는 장면
   - 게임이면 세계관·주인공·목표·끝나는 조건
   - 도구면 사용 순서
5. 핵심 특징 3–5가지
6. 기기와 조작 (§6-1)
   - 주로 쓸 기기: 스마트폰·태블릿 / PC / 둘 다 (폰이면 세로·가로도)
   - 조작 방식: 아래 셋 중에서 예를 들어 고르게 합니다. 사용자가 모르겠다고 하면 앱 종류에 맞는 것을 추천합니다.
     - 터치만: 화면이나 물체를 눌러 진행 (퀴즈, 퍼즐, 카드)
     - 화면 컨트롤러: 화면 아래 왼쪽에 방향, 오른쪽에 버튼 (점프·슈팅 같은 액션 게임)
     - 키보드·마우스: PC 전용
7. 그래픽 스타일: 픽셀아트, 실사풍, 손그림, 플랫 일러스트, 3D 로우폴리, 미니멀 등 / 색감 / 분위기
8. 소리: 효과음, 배경음악이 필요한지
9. 저장할 것: 점수, 기록, 설정 등
10. 꼭 넣고 싶은 것, 넣지 말았으면 하는 것

## 1. BeBeam이 무엇인가 (규칙의 이유)

**비빔 BeBeam**(https://www.bebeam.net/)은 내가 만든 작은 웹앱을 폰·태블릿·PC에 담아 실행하고, 친구에게 **네트워크 없이** 보내는 플레이어입니다. 설치형 PWA이며, 게임·수업자료·도구 같은 앱을 담습니다.

- **설치**
  - 사용자가 폴더나 zip을 넣으면, 플레이어가 파일을 기기 안(IndexedDB)에 저장합니다.
  - 서버에 올리지 않습니다.
- **실행**
  - 앱은 격리된 `sandbox` iframe(opaque origin) 안에서 실행됩니다.
  - 파일은 Blob URL로 된 가상 파일시스템으로 제공됩니다. 그래서 **앱 안의 상대경로만** 풀립니다.
  - **외부 통신은 CSP로 전부 막힙니다.** 받은 앱이 사용자 정보를 밖으로 보내지 못하게 하려는 것입니다.
  - 저장은 `localStorage`뿐이며, 플레이어가 앱마다 따로 보관합니다.
- **전송**
  - 앱 폴더를 zip으로 묶어 화면의 **QR 애니메이션**으로 보냅니다(단방향, fountain code).
  - 받는 사람은 카메라로 비추기만 합니다. 여러 명이 한 화면을 동시에 받을 수 있습니다.
  - 크기가 곧 전송 시간이므로 **작게** 만드는 것이 중요합니다.
- **화면**
  - 앱은 전체화면으로 실행됩니다.
  - 오른쪽 위에 플레이어의 반투명 ✕(종료) 버튼이 겹쳐 보입니다.
  - 대부분 폰에서 터치로 씁니다.

사용 설명: https://github.com/mcnorton/bebeam

## 2. 폴더 구조 — `index.html`로 시작

```
my-app/
├── index.html      ← 진입점 (폴더 맨 위, 필수)
├── style.css
├── main.js
├── icon.png        ← 파비콘·목록 아이콘 (필수, §5)
├── screenshot.webp ← 대표 스크린샷 (필수, og:image, §5-1)
├── assets/
│   ├── sprite.webp
│   └── jump.mp3
├── .gitignore      ← 배포에서 뺄 목록 (§2-1, 설치되지 않음)
└── .work/          ← 작업용 스크립트·임시 파일 (§2-1, 설치·전송되지 않음)
```

- 폴더 **맨 위에 `index.html`**이 있어야 합니다. 상위 폴더 하나로 감싼 zip도 됩니다.
  - 이름은 정확히 소문자 `index.html`입니다. `Index.html`, `index.htm`이면 설치가 거부됩니다.
  - 한 파일짜리 앱도 이름은 `index.html`입니다. `테트리스.html`처럼 다른 이름이면 설치가 거부됩니다.
- **HTML 파일이 여러 개면** (예: 스테이지마다 한 페이지)
  - 시작 화면은 반드시 `index.html`입니다. BeBeam은 언제나 `index.html`부터 엽니다.
  - 다른 HTML 파일은 모두 `index.html`에서 `<a href="stage1.html">` 링크를 따라 닿을 수 있어야 합니다. 링크로 닿지 않는 페이지는 열 수 없습니다.
  - 각 페이지에 `index.html`로 돌아오는 링크(예: [처음으로])를 넣습니다.
  - 제목·설명·아이콘·대표 스크린샷은 `index.html`의 것만 씁니다.
- 모든 참조는 **상대경로**로 씁니다. 예: `./assets/sprite.webp`, `assets/jump.mp3`.
  - `/`로 시작하는 절대경로는 쓰지 마세요.
  - `http://`, `https://`, `//`로 시작하는 주소도 쓰지 마세요.
- **경로 규칙**
  - 255자 이하
  - `..`(상위 폴더), 드라이브 문자(`C:`), 제어문자를 쓰지 않습니다. 하나라도 있으면 설치 전체가 거부됩니다.
  - 대소문자는 실제 파일명과 똑같이 씁니다.
- **파일·폴더 이름** (Windows·macOS·폰에서 모두 같게 열리도록)
  - 영문 소문자, 숫자, `-`, `_`만 씁니다. 예: `stage-1.webp`, `jump_sound.mp3`.
  - 한글·공백 이름은 피합니다. Windows 기본 압축으로 만든 zip에서 이름이 깨져 참조가 끊어질 수 있습니다.
  - 대소문자만 다른 두 파일(`Logo.png`와 `logo.png`)을 두지 않습니다. Windows·macOS는 같은 파일로 봅니다.
  - `con`, `nul`, `aux`, `prn`, `com1`, `lpt1` 같은 Windows 예약 이름, `< > : " | ? *` 문자, 끝이 점이나 공백인 이름을 쓰지 않습니다.
  - **실행에 필요한 파일·폴더 이름은 `.`으로 시작하지 않습니다** (§2-1).
- **자동 제외**: `.`으로 시작하는 파일·폴더, `node_modules/`, `__MACOSX/`, `Thumbs.db`. 설치되지 않으므로 친구에게 전송되지도 않습니다.
- **빌드 없이 그대로 동작하는 HTML·CSS·JavaScript**로 만드는 것이 기본입니다.
  - 번들러(Vite 등)를 썼다면 빌드 결과 폴더(`dist/`)만 넣습니다.
  - 이때 base를 `./`로 설정해 상대경로가 되게 합니다.

### 2-1. 작업 폴더 정리 — `.work/`와 `.gitignore`

AI가 개발하면서 만든 테스트·캡처·변환 스크립트, 임시 이미지, 로그가 앱 폴더에 남으면 함께 설치되고 친구에게까지 전송됩니다. 전송 시간이 늘고, 받은 사람 목록에 쓸모없는 파일이 들어갑니다.

- **앱 폴더에는 실행에 필요한 파일만** 둡니다.
- **작업용 파일은 모두 `.work/` 폴더 안에** 만듭니다. 처음부터 그곳에 만들고, 다른 곳에 생겼으면 옮깁니다.
  - 예: 스크린샷 캡처 스크립트(`.work/capture.mjs`), 이미지 변환·압축 스크립트, 테스트 코드, 임시 캡처 이미지, 로그, 작업 메모, 원본 그림(psd·고해상도 png)
  - 도구를 설치해야 하면(`npm install playwright` 등) `.work/` 안이나 앱 폴더 밖에 설치합니다. 앱 폴더 맨 위에 `package.json`·`node_modules/`를 만들지 않습니다.
- **`.`으로 시작하는 파일·폴더는 "내 앱에 추가"할 때 설치되지 않고, 그래서 전송되지도 않습니다.** 그러니 거꾸로, 실행에 필요한 파일·폴더 이름은 절대 `.`으로 시작하면 안 됩니다. `./.data/words.json`, `.hidden.png`처럼 참조하면 설치한 앱에서 파일을 찾지 못합니다.
- 폴더 맨 위에 **`.gitignore`**를 만들고 배포에서 뺄 파일·폴더를 적습니다. git이나 다른 곳(GitHub Pages 등)에 올릴 때 쓰는 목록입니다. BeBeam은 `.gitignore`를 읽지 않습니다. BeBeam에서는 `.`으로 시작하는 이름만 빠지므로, 뺄 것은 `.work/`에 넣는 것이 원칙입니다.

  ```gitignore
  # 작업용 스크립트·임시 파일 (BeBeam에 설치·전송되지 않음)
  .work/
  # 도구·운영체제가 만드는 파일
  node_modules/
  .DS_Store
  Thumbs.db
  desktop.ini
  *.log
  ```
- 다 만든 뒤 폴더 맨 위를 다시 봅니다. 앱 파일이 아닌 것이 남아 있으면 `.work/`로 옮깁니다.
- **zip으로 묶을 때**는 `.`으로 시작하는 항목을 빼고 묶으면 작고 빠릅니다(넣어도 설치 때 빠지지만, zip 크기 상한 100MB·항목 수 5,000개에는 포함됩니다). 폴더째 추가할 때는 그대로 골라도 됩니다.
  - macOS·Linux (앱 폴더 안에서): `zip -r ../my-app.zip . -x '.*' '*/.*'`
  - Windows PowerShell (앱 폴더 안에서): `Compress-Archive -Path (Get-ChildItem -Exclude '.*').FullName -DestinationPath ..\my-app.zip`
  - Windows 탐색기와 달리 macOS Finder는 `.`으로 시작하는 파일을 숨겨 보여 주지 않습니다. Windows에서는 `.work` 폴더가 그대로 보이지만 BeBeam에는 들어가지 않습니다.

| 분류 | 확장자 |

## 4. HTML·CSS·JavaScript 작성 규칙

### 되는 것
- ES 모듈: `<script type="module" src="main.js">`, `import { x } from './lib/x.js'`
- 문자열 리터럴로 쓴 dynamic import: `import('./levels/1.js')`
  - 모듈 파일(`.js`)이나 `type="module"` 스크립트 안에서만 됩니다.
- 앱 안 파일 읽기: `fetch('./data/words.json')`, `XMLHttpRequest`
- 코드로 경로를 만들어 쓰기: `img.src = 'assets/' + name + '.webp'`, `new Audio('assets/jump.mp3')`
  - JS로 풀리는 경로는 `img`·`audio`·`video`·`source`·`script`·`link`의 `src`·`href`(속성·`setAttribute`)뿐입니다.
  - `el.style.backgroundImage = 'url(…)'`처럼 **JS로 넣는 CSS `url()`은 풀리지 않습니다.** 배경 이미지는 CSS 파일에 클래스로 적어 두고 클래스를 바꾸거나, `<img>`를 씁니다.
  - `fetch`에는 문자열 경로를 넘깁니다(`new Request(…)` 객체는 쓰지 않습니다).
- canvas, WebGL, Web Audio, wasm, `requestAnimationFrame`
- 인라인 `<script>`·`<style>`, `eval`, `new Function`
- 전체화면, 게임패드, pointer lock, `alert`·`confirm`·`prompt`
- `<form>`: `submit` 이벤트에서 `e.preventDefault()`를 하고 JS로 처리합니다. action으로 제출하면 막힙니다.
- 단일 파일 Web Worker: `new Worker('worker.js')`
  - 워커 안에서는 import도 파일 읽기(`fetch`)도 안 됩니다. 필요한 데이터는 `postMessage`로 넘깁니다.
- 다른 HTML 페이지로 가는 링크(`<a href="page2.html">`): 클릭하면 같은 앱 안에서 이동하며 저장소를 함께 씁니다. 시작은 언제나 `index.html`입니다(§2).
  - 화면 전환은 한 페이지 안에서 JS로 요소를 바꾸는 방식이 가장 안전합니다.
- 저장: **`localStorage`** (앱마다 5MB, 키와 값을 글자당 2바이트로 셈 = 약 260만 글자, 실행을 끝내도 남음)
  - `sessionStorage`는 실행을 끝내면 사라집니다.
  - **키에는 앱 고유 접두사를 붙입니다.** 영문 소문자 앱 id와 `:`를 쓰고, 한 곳에서 정해 씁니다.
    - 예: `const KEY = 'jump-rabbit:';` → `localStorage.setItem(KEY + 'best', score)`
    - 이유: BeBeam 안에서는 앱마다 저장소가 따로라 섞이지 않습니다. 그러나 개발 중 `localhost`나 `username.github.io` 같은 공유 주소에서 열면 같은 주소의 다른 앱과 `score`·`settings` 같은 키가 섞여 덮어써집니다.
  - `localStorage.clear()`는 쓰지 않습니다. 지울 때는 내 접두사가 붙은 키만 지웁니다.
  - 여러 값은 한 키에 JSON으로 묶어 저장합니다. 예: `KEY + 'settings'`에 `JSON.stringify({ sound: true })`.
  - 읽기와 쓰기는 `try/catch`로 감쌉니다. 저장소가 막힌 환경이나 용량 초과(`QuotaExceededError`)에서도 앱이 멈추지 않게 합니다.

### 안 되는 것 (조용히 실패하거나 오류가 납니다)
| 안 됨 | 대신 |
|---|---|
| CDN 스크립트·CSS (`<script src="https://cdn...">`) | 라이브러리 파일을 폴더에 넣고 상대경로로 |
| 웹 폰트 (Google Fonts 등) | woff2 파일을 넣거나 시스템 폰트 |
| 외부 API·`fetch('https://…')`·WebSocket·EventSource | 데이터는 JSON 파일로 포함. 온라인 기능은 만들 수 없음 |
| bare import (`import * as THREE from 'three'`) | `import * as THREE from './lib/three.module.js'` |
| 순환 import (a.js ↔ b.js) | 공통 부분을 별도 모듈로 분리 |
| **JS로 페이지 이동**: `location.href = …`, `location.reload()`, `location.assign()` | **앱이 강제 종료됩니다.** `<a href>` 클릭이나 한 페이지 안 화면 전환 |
| `<form action>` 제출 | `submit`에서 `preventDefault()` 후 JS 처리 |
| `<iframe>`, `<object>`, `<embed>`, `<base>`, `<meta http-equiv="refresh">` | `<a href>` 이동, `fetch`로 읽어 화면에 그리기 |
| 변수·템플릿으로 만든 import 경로 (`import('./lv' + n + '.js')`), 클래식 `<script>` 안의 `import()` | 정적 import로 모두 불러 두고 고르기, 데이터는 JSON + `fetch` |
| JS로 넣는 CSS `url()` (`style.backgroundImage`, `cssText`, 동적 `<style>`, `insertRule`) | CSS 파일의 클래스 바꾸기, `<img>` |
| `indexedDB`, 쿠키, Cache API, Service Worker | `localStorage`에 JSON으로 |
| WebRTC, `window.open`·팝업, `target="_top"`, 다운로드 | 앱 안 화면으로 처리 |
| 카메라·마이크·위치 | 사용 불가 |
| Worker 안의 `import`·`importScripts` | 워커는 파일 하나로 |
| 외부 링크(`<a href="https://…">`) | 앱 밖으로 나갈 수 없음 |

라이브러리는 **ES 모듈 빌드(`*.module.js`, `*.esm.js`)** 나 전역 스크립트 빌드(`*.min.js`) 파일을 폴더에 넣어 쓰세요.

## 5. 메타데이터 (목록에 예쁘게 보이게)

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
  <title>점프 토끼</title>                                   <!-- 앱 이름, 60자까지 -->
  <meta name="description" content="화면을 눌러 토끼를 점프시키는 게임">  <!-- 설명, 200자까지 -->
  <link rel="icon" href="icon.png">                          <!-- 파비콘·목록 아이콘 (필수. 앱 안의 정사각형 PNG·SVG 파일. data:·외부 주소는 무시) -->
  <meta property="og:image" content="screenshot.webp">       <!-- 대표 스크린샷 (필수): 실행 전 뷰어 배경 (§5-1) -->
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <script type="module" src="main.js"></script>
</body>
</html>
```

- `<title>`이 없으면 폴더 이름이 앱 이름이 됩니다.
- **파비콘은 꼭 넣으세요.** 앱 목록에서 앱을 알아보는 그림입니다.
  - 정사각형 `icon.png`(192×192 이상, 50KB 이하) 또는 `icon.svg`를 폴더 맨 위에 두고 `<link rel="icon">`으로 가리킵니다.
  - 앱의 그래픽 스타일로, 작게 보여도 알아볼 수 있는 단순한 그림으로 만듭니다. 글자는 넣지 않거나 한 글자만 씁니다.
  - `<link rel="icon">`이 없으면 `favicon.ico`·`favicon.png`·`favicon.svg`·`icon.png` 순서로 찾고, 그래도 없으면 기본 아이콘이 보입니다.

### 5-1. 대표 스크린샷 (필수)

목록에서 앱을 고르면, 실행하기 전 뷰어 화면에 **`og:image`로 지정한 이미지가 배경으로 꽉 차게** 깔립니다. 그 위에 앱 이름과 [▶ 실행하기]·[앱 보내기] 버튼이 놓입니다. 이미지가 없으면 그냥 검은 화면이라, 대표 스크린샷 한 장이 앱의 첫인상을 정합니다.

- **무엇을 찍나**: 실제 실행 화면 중 **가장 멋진 장면**을 간단하게 담습니다. 게임이면 플레이 중인 화면, 도구면 데이터가 채워진 화면입니다. 빈 시작 화면이나 로딩 화면은 피합니다.
- **앱 제목을 넣지 않습니다.** 플레이어가 앱 이름을 이미지 위에 겹쳐 쓰므로, 제목이 들어가면 두 번 보이고 겹칩니다. 제목 화면(타이틀 로고)이 아니라 실행 중인 장면을 씁니다.
- **파일**
  - 앱 폴더 맨 위에 `screenshot.webp`로 둡니다. `.png`·`.jpg`도 됩니다.
  - `<meta property="og:image" content="screenshot.webp">`로 **앱 안의 파일을 상대경로로** 가리킵니다. 외부 주소의 이미지는 가져오지 않습니다.
- **크기와 구도**
  - 1200×630(가로형)을 권장합니다. 세로로 길게 쓰는 앱이면 720×1280도 됩니다.
  - 뷰어 모양(폰 세로, PC 가로)에 맞춰 **가장자리가 잘리고 가운데가 보입니다**. 중요한 장면은 가운데에 두세요.
  - 이미지는 어둡게(약 55%) 깔리고 가운데에 흰 글자·버튼이 올라갑니다. 너무 어두운 장면보다 색이 분명한 장면이 잘 보입니다.
- **용량**: 전송 시간에 포함되므로 webp 품질 70–80, **200KB 이하**로 저장합니다.
- **만드는 방법**
  - **AI가 브라우저를 실행해 화면을 캡처할 수 있으면**, 직접 실행해 대표 장면을 찍어 `screenshot.webp`로 저장합니다.
  - **캡처할 수 없으면**, 사용자에게 요청합니다. 어떤 장면을 찍을지 구체적으로 알려 주고(예: "적이 셋 이상 나오고 점수가 올라간 플레이 화면"), "앱을 열어 그 장면을 캡처한 뒤 `screenshot.webp`(또는 `.png`)로 폴더 맨 위에 저장해 주세요"라고 안내합니다. `og:image` 태그는 미리 넣어 둡니다. 파일이 빠지면 배경이 검정으로 보이므로, 보내기 전에 꼭 넣게 합니다.

## 6. 화면

- **세로와 가로 모두** 깨지지 않게 만드세요(`100dvh`, flex/grid, `vmin`).
- **터치 우선**
  - 버튼은 최소 44px로 만듭니다.
  - 게임 화면에는 `touch-action: none`을 씁니다.
  - hover에만 기대지 않습니다.
- 오른쪽 위 모서리(약 56×56px, 노치 기기는 안전영역만큼 더 안쪽)는 플레이어의 ✕ 버튼이 덮습니다. 중요한 버튼을 두지 마세요.
- 인터넷이 없어도 동작해야 합니다(실제로 오프라인에서 실행됩니다).
- 글꼴은 시스템 글꼴(`system-ui, sans-serif`)을 권장합니다. 폰트 파일은 용량이 큽니다.

### 6-1. 조작 인터페이스 — 기기에 맞춰 고르기

**먼저 대상 기기를 정합니다.** 새로 만드는 앱은 사용자에게 묻고(§0 묻는 항목 6), 이미 만든 앱은 AI가 콘텐츠의 시나리오를 보고 정합니다(§12). 그다음 아래 유형 중 하나를 고릅니다.

| 시나리오 | 유형 |
|---|---|
| 화면·물체를 눌러 진행 (퀴즈, 퍼즐, 카드, 클리커, 턴제, 그림책·수업자료, 도구) | 1. 터치만 |
| 한 번 누르기만 하는 실시간 게임 (탭해서 점프, 원 버튼 게임) | 1. 터치만 (배경 탭) |
| 이동하면서 동시에 행동하는 실시간 게임 (플랫폼, 슈팅, 레이싱, 액션) | 2. 화면 컨트롤러 |
| PC에서만 쓰는 앱 | 3. 키보드·마우스 |
| 폰·태블릿과 PC 둘 다 | 1 또는 2 + 3 |

- **유형 1. 터치만 (컨트롤러 없음)**
  - 배경 탭, 물체 탭·드래그, 스와이프로 진행합니다. 화면에 버튼 패드를 두지 않습니다.
  - 누르는 대상은 44px 이상으로 만들고, `click` 또는 Pointer Events로 받습니다(마우스로도 그대로 됩니다).
- **유형 2. 화면 컨트롤러 (스마트폰·태블릿에서 여러 입력이 필요할 때)**
  - **화면 아래 왼쪽**에 방향(십자 패드나 조이스틱), **아래 오른쪽**에 행동 버튼(A·B, 2–3개까지)을 둡니다.
  - 버튼은 64px 이상(최소 44px), 반투명으로 만들고 안전영역(`env(safe-area-inset-bottom)`, `left`, `right`)만큼 안쪽에 둡니다. 오른쪽 위 ✕ 자리는 피합니다.
  - 여러 손가락을 동시에 받도록 Pointer Events(`pointerdown`·`pointerup`·`pointercancel`, `setPointerCapture`)를 씁니다. 손가락이 버튼 밖으로 나가도 떼었을 때 풀리게 합니다.
  - 컨트롤러에 `touch-action: none`, `user-select: none`을 주고 `contextmenu`를 막아 길게 눌러도 메뉴·확대가 뜨지 않게 합니다.
  - 세로 화면에서는 게임 화면이 컨트롤러에 가리지 않게 아래에 컨트롤러 띠를 따로 두고, 가로 화면에서는 게임 위 양쪽 아래 모서리에 겹쳐 둡니다.
  - 화면 버튼은 **키보드와 같은 입력 상태**를 바꿉니다(예: `input.left = true`). 게임 로직을 두 벌로 만들지 않습니다.
  - 터치 기기에서만 보입니다. `matchMedia('(any-pointer: coarse)')`로 판단하거나 첫 터치 때 보이게 합니다.
- **유형 3. PC (키보드·마우스)**
  - 방향키·WASD로 이동하고 Space·Enter로 행동합니다. 마우스 클릭도 받습니다.
  - 시작 화면에 조작 키 안내를 둡니다.
  - hover·우클릭·휠에만 기대는 기능은 만들지 않습니다.
- **둘 다**: 유형 1 또는 2에 키보드를 함께 지원합니다. 컨트롤러는 터치 기기에서만 보입니다.

## 7. 용량과 전송 시간

| 항목 | 상한 |
|---|---|
| 앱 전체 (압축 풀었을 때) | 50MB |
| 파일 수 | 1,000개 |
| 파일 하나 | 20MB |
| **전송 권장 (zip 압축 후)** | **2MB 이하** (넘으면 예상 시간을 경고, 막지는 않음) |

- **QR 전송은 대략 1MB에 1분 정도** 걸립니다. 보통 속도 기준이며, 기기와 조명에 따라 더 걸립니다.
  - **압축 후 1MB 이하를 목표로** 하세요. 수업 시간에 여러 명이 기다리면서 받는다고 생각하면 됩니다.
- **줄이는 방법**
  - 이미지: webp로 저장하고, 화면에 보이는 크기에 맞춘 해상도로 만듭니다(보통 1024px 이하).
  - 오디오: 짧은 효과음은 mp3·ogg 64–96kbps로 만듭니다. 배경음악은 짧게 반복합니다.
  - 그림은 가능하면 canvas·SVG·CSS로 **코드로 그립니다**.
  - 큰 라이브러리(전체 three.js, 게임 엔진)보다 필요한 기능만 직접 짭니다.
  - 폰트 파일은 넣지 않거나, 쓰는 글자만 서브셋으로 만듭니다.
  - png·jpg·mp3·mp4는 이미 압축된 파일이라 zip으로 거의 줄지 않습니다. 코드·JSON은 많이 줄어듭니다.

## 8. BeBeam에 넣는 방법 (사용자에게 안내할 것)

1. https://www.bebeam.net/ 에서 [BeBeam 실행]을 누르고 플레이어를 설치합니다.
   - iPhone·iPad: 공유 → 홈 화면에 추가
   - Mac Safari: 파일 → Dock에 추가
2. 목록 아래 **[＋ 나의 앱 추가]**를 누르고 넣습니다.
   - **폴더 추가**: PC에서 `index.html`이 들어 있는 폴더를 선택합니다.
   - **zip 파일 추가**: 폴더를 zip으로 묶어 선택합니다. 폰에서는 이 방법을 씁니다.
3. 목록에서 앱을 고르고 ▶를 눌러 실행합니다.
4. 친구에게 보낼 때는 **[앱 보내기]**를 누릅니다. 친구는 **[＋ 나의 앱 추가] → [QR로 받기]**를 누르고 카메라로 QR을 비춥니다.

만들면서 PC에서 확인할 때는 파일을 더블클릭(`file://`)하지 마세요. 모듈·fetch가 막힙니다. 대신 폴더에서 `python3 -m http.server`(Windows는 `py -m http.server`)를 실행하고 http://localhost:8000 으로 엽니다.

## 9. AI 자가 점검표

- [ ] 폴더 맨 위에 소문자 `index.html`이 있다
- [ ] 작업용 스크립트·임시 파일은 모두 `.work/` 안에 있고, 폴더에는 실행에 필요한 파일만 있다
- [ ] 실행에 필요한 파일·폴더 이름은 `.`으로 시작하지 않고, 영문 소문자·숫자·`-`·`_`로 되어 있다
- [ ] `.gitignore`에 `.work/` 등 배포에서 뺄 목록이 있다
- [ ] `http://`, `https://`, `//`로 시작하는 참조가 **하나도 없다** (script, link, img, CSS `url()`, `import`, `fetch`)
- [ ] 모든 경로가 상대경로이고, 대소문자가 실제 파일명과 같다
- [ ] 모든 파일이 §3 허용 확장자다 (`.ts`·`.jsx`는 빌드 결과로 바꿨다)
- [ ] bare import·순환 import·변수로 만든 import 경로가 없다
- [ ] `location.href`·`location.reload()` 이동, `<iframe>`, form action 제출, JS로 넣는 CSS `url()`이 없다
- [ ] 저장은 `localStorage`만 쓴다 (indexedDB·쿠키 없음)
- [ ] `localStorage` 키에 앱 접두사(`my-app:`)가 붙어 있고 `clear()`를 쓰지 않는다
- [ ] HTML 파일이 여러 개면 모두 `index.html`에서 링크로 닿고, 각 페이지에 `index.html`로 돌아오는 링크가 있다
- [ ] `<title>`, `<meta name="description">`이 있다
- [ ] 파비콘(정사각형 `icon.png` 또는 `icon.svg`)이 있고 `<link rel="icon">`이 가리킨다
- [ ] 대표 스크린샷 `screenshot.webp`(200KB 이하)가 폴더 맨 위에 있고 `<meta property="og:image" content="screenshot.webp">`가 가리킨다 (캡처할 수 없으면 사용자에게 요청했다)
- [ ] 대표 스크린샷에 앱 제목이 없고, 실제 실행 화면 중 가장 멋진 장면이다
- [ ] 세로·가로, 폰 너비(360px)에서 깨지지 않고 터치로 조작된다
- [ ] 오른쪽 위 모서리에 중요한 버튼이 없다
- [ ] 대상 기기에 맞는 조작 유형(§6-1)을 골랐다
- [ ] 화면 컨트롤러가 있다면 아래 왼쪽(방향)·오른쪽(버튼)에 있고, 터치 기기에서만 보이며, 두 손가락을 동시에 눌러도 된다
- [ ] (변환이면, §12) 원본 폴더는 그대로이고 복사본만 고쳤다
- [ ] (변환이면, §12) 콘텐츠를 바꾸지 않았다. 바꾼 것은 모두 사용자의 승인을 받았다
- [ ] zip으로 압축하면 **2MB 이하**다 (목표 1MB)
- [ ] `python3 -m http.server`로 열고 인터넷을 끊어도 동작한다

- 대표 스크린샷을 직접 캡처하지 못했다면, 어떤 장면을 어떻게 캡처해 `screenshot.webp`로 저장하면 되는지 (§5-1)
- `.work/`에 무엇이 남았는지. 앱 실행에는 필요 없으므로 지워도 되고, 고칠 때 다시 쓰려면 두어도 됩니다(BeBeam에 들어가지 않음)
- BeBeam에 넣는 방법 (§8): 폴더째 추가하거나, `.`으로 시작하는 항목을 빼고 zip으로 묶는 방법 (§2-1)
- 이미 만든 앱을 바꿨다면 §12의 보고 항목

## 12. 이미 만든 앱을 BeBeam용으로 바꾸기

사용자가 이미 만든 웹앱을 주며 BeBeam에서 실행되게 해 달라고 했을 때의 규칙입니다. 목표는 **원본과 똑같이 동작하는 BeBeam용 복사본**입니다.

### 가장 중요한 원칙 — 콘텐츠는 승인 없이 절대 손대지 않습니다
- **콘텐츠**: 글·대사·문제·정답, 그림·소리·영상, 레벨·규칙·점수·난이도, 화면 디자인과 배치, 기능. 사용자가 만든 작품 그 자체입니다.
- **바꿔도 되는 것**: BeBeam에서 실행되게 하는 **기술적인 부분뿐**입니다(아래 "묻지 않고 자동으로 하는 것"). 바꾼 뒤에도 원본과 똑같이 보이고 똑같이 동작해야 합니다.
- 콘텐츠를 바꿔야만 BeBeam에서 돌릴 수 있다면(온라인 랭킹, 외부 API, 로그인, 카메라 등) **작업을 멈추고**, 왜 안 되는지와 대안을 보여 준 뒤 사용자가 승인한 것만 바꿉니다.
- 더 좋게 만들 아이디어(버그 수정, 디자인 개선, 기능 추가)가 있어도 몰래 넣지 않습니다. 보고 때 제안만 합니다.

### 원본 보존
- **원본 폴더는 고치거나 지우지 않습니다.** 옆에 복사본 `<원래 이름>-bebeam/`을 만들어 그 안에서만 작업합니다. 예: `space-game/` → `space-game-bebeam/`
- 변환에 쓴 원본 소스(`.ts` 등)·설정·스크립트는 복사본의 `.work/`에 둡니다(§2-1).

### 순서
1. **살펴보기**: 파일 목록, 시작 HTML, 빌드 도구(`package.json`, Vite·webpack 등), 외부 참조(CDN·폰트·API), 저장 방식, 조작 방식, 원래 대상 기기를 확인합니다.
2. **점검 결과를 짧게 보여 줍니다**: ① 그대로 되는 것 ② 자동으로 고칠 것 ③ 물어볼 것.
3. **"물어볼 것"만 묻습니다.** 자동 항목은 묻지 않고 진행합니다. 물어볼 것이 없으면 바로 진행합니다.
4. 복사본을 만들고 변환합니다.
5. §9 점검표를 하나씩 확인하고, 할 수 있으면 `python3 -m http.server`로 열어 원본과 같게 동작하는지 봅니다.
6. 아래 "보고"대로 알립니다.

### 묻지 않고 자동으로 하는 것
- **시작 파일**: 시작 HTML을 소문자 `index.html`로 이름을 바꾸고, 그 파일을 가리키던 링크도 고칩니다. 한 파일짜리 앱(`game.html`)도 `index.html`이 됩니다.
- **TS·JSX·TSX → JS**
  - 프로젝트에 빌드가 있으면 base를 `./`로 해서 빌드하고, 결과 폴더(`dist/`) 내용만 복사본에 넣습니다(§2).
  - 빌드가 없으면 타입 표기만 지우는 변환(예: `esbuild`, `tsc`)으로 `.js`를 만듭니다. 로직은 한 줄도 바꾸지 않습니다.
- **외부 참조 → 앱 안 파일 (§4)**
  - CDN 라이브러리·웹 폰트는 **같은 버전**의 파일을 받아 `lib/`·`fonts/`에 넣고 상대경로로 바꿉니다. 받을 수 없으면 어떤 파일이 필요한지 알려 주고 사용자에게 요청합니다.
  - bare import(`from 'three'`)와 `/`로 시작하는 절대경로는 상대경로로 바꿉니다.
- **BeBeam에서 막히는 코드 → 같은 동작의 코드 (§4)**
  - `location.reload()`·`location.href = …` 다시 시작 → 처음 상태로 되돌리는 함수
  - JS로 넣는 CSS `url()` → CSS 파일의 클래스나 `<img>`
  - indexedDB·쿠키 저장 → `localStorage`(같은 데이터를 JSON으로)
  - `localStorage` 키에 앱 접두사 붙이기, `clear()` → 내 키만 지우기
  - `<form action>` 제출 → `submit`에서 `preventDefault()` 후 같은 처리
- **이름 (§2·§3)**: 규칙에 맞지 않는 파일·폴더 이름(한글·공백·대문자, `.`으로 시작하는 실행 파일)은 바꾸고 참조도 모두 고칩니다. 허용되지 않는 확장자의 런타임 파일은 허용 확장자로 바꿉니다(예: 읽어 쓰는 `.md` → `.txt`).
- **메타데이터 (§5)**
  - `<title>`: 원본의 제목을 그대로 씁니다. 없으면 화면에 보이는 앱 이름을 씁니다.
  - `<meta name="description">`: 앱 안의 글을 바탕으로 한 문장으로 씁니다.
  - `<meta name="viewport">`가 없으면 넣습니다.
- **아이콘 (§5)**: 원본에 아이콘이 있으면 그대로 씁니다. 없으면 앱 안의 그림(주인공·대표 물체)을 정사각형으로 잘라 `icon.png`를 만들거나, 앱의 색으로 단순한 `icon.svg`를 만듭니다. **새 파일을 더할 뿐, 원래 그림은 바꾸지 않습니다.**
- **대표 스크린샷 (§5-1)**: 직접 실행해 가장 멋진 장면을 캡처합니다. 캡처할 수 없으면 §5-1대로 사용자에게 요청합니다.
- **작업 파일 (§2-1)**: 실행에 필요 없는 파일(설정, 테스트, 원본 소스, 메모)은 `.work/`로 옮기고 `.gitignore`를 씁니다.
- **조작 (§6-1)**: **원래 조작은 그대로 두고**, 콘텐츠의 시나리오를 보고 AI가 유형을 골라 **더합니다**.
  - 예: 방향키+Space로 하는 액션 게임 → 아래 왼쪽 방향·오른쪽 버튼의 화면 컨트롤러를 더합니다(터치 기기에서만 보임).
  - 예: 클릭으로 진행하는 퀴즈 → 터치가 곧 클릭이므로 더하지 않습니다.

### 반드시 묻는 것 (짐작해서 진행하지 않습니다)
- **스마트폰·태블릿에서 어떻게 조작할지 분명하지 않을 때**
  - 키가 많을 때: 어떤 키를 화면 버튼으로 둘지 (예: "Z·X·C·Shift 중 화면 버튼으로 둘 2개를 골라 주세요")
  - 마우스 hover·우클릭·휠, 정밀한 드래그, 키 동시 입력에 기대는 조작
  - 원래 PC 전용인데 폰에서도 쓸지
- **콘텐츠를 바꿔야만 되는 것**: 외부 서버·온라인 기능·로그인·카메라·마이크를 빼거나 바꾸는 것
- **이미지·소리를 다시 압축하거나 줄이는 것**: 화질·음질이 바뀌므로 묻습니다. 압축 후 2MB를 넘으면 줄이는 방법과 예상 크기를 제안합니다(§7).
- **화면 배치를 옮겨야 할 때**: 예: 오른쪽 위 ✕ 자리(§6)에 중요한 버튼이 있을 때
- **시작 HTML이 여럿이라 어느 것이 시작인지 분명하지 않을 때**
